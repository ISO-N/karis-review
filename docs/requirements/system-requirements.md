# 系统需求 — Karis Review 闪卡复习软件

## 1. 系统架构

### 1.1 架构概览

```
┌──────────────────────┐      HTTP/API       ┌──────────────────────┐
│   Flutter 客户端      │ ◄─────────────────► │   Java 后端服务       │
│   (桌面 + 移动端)     │      JSON/HTTPS      │   (REST API)          │
│                      │                      │                      │
│   - 纯 UI 层          │                      │   - 业务逻辑层         │
│   - 无本地数据存储     │                      │   - 数据持久化层        │
│   - 排版渲染引擎       │                      │   - 排期算法引擎        │
└──────────────────────┘                      └──────────┬───────────┘
                                                          │
                                                          ▼
                                                  ┌──────────────────┐
                                                  │   数据库          │
                                                  │   (PostgreSQL/)   │
                                                  └──────────────────┘
```

### 1.2 设计原则

- **无状态客户端**：客户端仅负责 UI 渲染和用户交互，不保存任何业务数据。
- **服务端权威**：所有业务逻辑（排期计算、认证、数据校验）在服务端执行。
- **API 驱动**：客户端通过 REST API 与服务端通信，数据格式为 JSON。
- **自然日精度**：所有间隔计算按自然日（日历日）计算，不精确到小时。
- **自定义刷新时间**：用户可设定每日刷新时间，过了该时间点才算新的一天。
## 2. 排期算法（核心业务逻辑）

### 2.1 阶段定义

每张卡片在学习/复习过程中处于以下阶段之一：

| 阶段编号 | 名称 | 间隔（天） | 说明 |
|---------|------|-----------|------|
| Stage 0 | 学习阶段 | — | 新卡默认状态，通过后进入 Stage 1 |
| Stage 1 | 复习阶段 1 | 1 | 次日首次复习 |
| Stage 2 | 复习阶段 2 | 2 | — |
| Stage 3 | 复习阶段 3 | 4 | — |
| Stage 4 | 复习阶段 4 | 7 | — |
| Stage 5 | 复习阶段 5 | 15 | — |
| Stage 6 | 复习阶段 6 | 30 | — |
| Stage 7 | 复习阶段 7 | 90 | — |
| Stage 8 | 复习阶段 8 | 180 | 最终阶段 |

### 2.2 评分选项

每次复习时用户对卡片进行评分，共三个选项：

| 评分 | 标识 | 行为 |
|------|------|------|
| 忘记 | FORGET | 见 2.3 |
| 模糊 | VAGUE | 见 2.4 |
| 熟悉 | FAMILIAR | 见 2.5 |

### 2.3 FORGET 逻辑

**适用场景：** 用户完全不记得卡片内容。

**规则：**
1. 卡片阶段重置为 Stage 0（重新学习阶段）
2. 在重新学习期间，卡片以 **2^n 张卡间距**（n ≥ 0）插入复习队列：
   - 第 1 次插入：当前卡后隔 1 张卡（2⁰）
   - 第 2 次插入：再隔 2 张卡（2¹）
   - 第 3 次插入：再隔 4 张卡（2²）
   - 第 4 次插入：再隔 8 张卡（2³）
   - 以此类推
3. 每次插入时，卡片出现，用户评分
4. 用户需要累计 **5 次连续 Familiar** 才能脱离重新学习
5. 在累计过程中，如果用户对这张卡点了 **FORGET 或 VAGUE**，连续计数清零，但卡片**不继续降级**（仍留在重学流程中）
6. 集满 5 次连续 Familiar 后，卡片进入 Stage 1，次日开始正常复习

### 2.4 VAGUE 逻辑

**适用场景：** 用户对卡片内容有模糊印象，但不能完全回忆。

**规则：**
1. 卡片回退到**上一个 Stage**（例如 Stage 4 → Stage 3）
2. 进入重新学习阶段，期间以 **2^n 张卡间距**插入队列（同 FORGET 机制）
3. 用户需要累计 **3 次连续 Familiar** 才能脱离重新学习
4. 在累计过程中，如果用户对这张卡点了 **FORGET 或 VAGUE**，连续计数清零，但卡片**不继续降级**（留在当前重学阶段）
5. 集满 3 次连续 Familiar 后，计算下次复习日期：
   - 间隔天数 = 当前 Stage 间隔 − 上一个 Stage 间隔
   - 例：Stage 4（7天）→ 模糊退回 Stage 3 → 重学完成后，下次复查在 7 − 4 = 3 天后
   - 到达复查日时，卡片回到原 Stage 再次接受复习
6. **特殊边界：** 若用户在 Stage 1 点 VAGUE，语义等同于 FORGET（Stage 0，5 次连续 Familiar，
   因为 Stage 1 没有更低的可退阶段）
### 2.5 FAMILIAR 逻辑

**适用场景：** 用户成功回忆出卡片内容。

**规则：**
1. 卡片前进到**下一个 Stage**
2. 下次复习日期 = 当前日期 + 新 Stage 对应的间隔天数
3. 例：Stage 3（4天）点 Familiar → Stage 4（7天）→ 7 天后复查

### 2.6 学习阶段（Stage 0）特殊规则

1. 新创建的卡片默认进入 Stage 0
2. 学习阶段同样提供 FORGET / VAGUE / FAMILIAR 三个选项
3. 点击 FORGET 或 VAGUE 时无后退语义（Stage 0 已是最低阶段），仅对当前卡片重复学习
4. 点击 FAMILIAR 后卡片进入 Stage 1，次日开始第一次正式复习
5. 学习阶段不涉及 2^n 插入间距机制，卡片按顺序逐一学习

> **时间精度说明：** 所有间隔天数均按自然日计算，例如 1 天后指下一个日历日，不考虑具体时间。
> 每日刷新点的判断依据用户的 `refresh_time` 设置。
### 2.7 算法状态机

```
                  ┌──────────────────────────────────────────────┐
                  │                                              │
                  ▼                                              │
  ┌──────────┐  Familiar  ┌──────────┐  Familiar  ┌──────────┐  │
  │ Stage 0  ├───────────►│ Stage 1  ├───────────►│ Stage 2  ├─►...
  │ (学习)   │            │ (1天)    │            │ (2天)    │
  └──────────┘            └──────────┘            └──────────┘
       ▲                       ▲  ▲                     ▲
       │                       │  │                     │
       │  FORGET               │  │ VAGUE(回退1个Stage) │
       │  (5次连续Familiar)     │  │ (3次连续Familiar)    │
       └───────────────────────┘  └─────────────────────┘
```

## 3. 数据模型

### 3.1 用户（User）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 主键 |
| email | VARCHAR(255) | 邮箱（唯一） |
| password_hash | VARCHAR(255) | 密码哈希 |
| created_at | TIMESTAMP | 注册时间 |
| updated_at | TIMESTAMP | 更新时间 |
| refresh_time | TIME | 每日刷新时间（用户自定义，默认 04:00） |
### 3.2 牌组（Deck）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 主键 |
| user_id | UUID | 外键 → User |
| name | VARCHAR(255) | 牌组名称 |
| created_at | TIMESTAMP | 创建时间 |
| updated_at | TIMESTAMP | 更新时间 |

### 3.3 卡片（Card）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 主键 |
| deck_id | UUID | 外键 → Deck |
| user_id | UUID | 外键 → User |
| front | TEXT | 正面内容（富文本/LaTeX/代码） |
| back | TEXT | 反面内容（富文本/LaTeX/代码） |
| stage | INTEGER | 当前阶段 (0-8) |
| consecutive_familiar | INTEGER | 重学期间连续 Familiar 计数 |
| next_review_date | DATE | 下次复习日期 |
| learning_mode | BOOLEAN | 是否处于重学模式（FORGET/VAGUE 后） |
| reentry_stage | INTEGER | 重学完成后需要回到的 Stage（仅 VAGUE） |
| created_at | TIMESTAMP | 创建时间 |
| updated_at | TIMESTAMP | 更新时间 |

### 3.4 复习记录（ReviewLog）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 主键 |
| card_id | UUID | 外键 → Card |
| user_id | UUID | 外键 → User |
| rating | ENUM(FORGET, VAGUE, FAMILIAR) | 评分 |
| stage_before | INTEGER | 复习前的阶段 |
| stage_after | INTEGER | 复习后的阶段 |
| reviewed_at | TIMESTAMP | 复习时间 |

### 3.5 备份快照（Backup）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 主键 |
| user_id | UUID | 外键 → User |
| data | JSONB | 用户全量数据快照 |
| created_at | TIMESTAMP | 创建时间 |

## 4. API 接口设计

### 4.1 认证

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | /api/auth/register | 邮箱注册 |
| POST | /api/auth/login | 登录，返回 Token |
| POST | /api/auth/logout | 登出 |

### 4.2 用户设置

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /api/settings | 获取当前用户设置 |
| PUT | /api/settings | 更新用户设置（如 refresh_time） |

### 4.3 牌组

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /api/decks | 获取当前用户所有牌组 |
| POST | /api/decks | 创建牌组 |
| PUT | /api/decks/{deckId} | 重命名牌组 |
| DELETE | /api/decks/{deckId} | 删除牌组（含卡片） |

### 4.4 卡片

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /api/decks/{deckId}/cards | 获取牌组内所有卡片 |
| POST | /api/decks/{deckId}/cards | 创建卡片 |
| POST | /api/decks/{deckId}/cards/import/preview | 解析并预览卡片 JSON 数组 |
| POST | /api/decks/{deckId}/cards/import | 导入卡片到当前牌组 |
| PUT | /api/cards/{cardId} | 编辑卡片 |
| DELETE | /api/cards/{cardId} | 删除卡片 |

### 4.5 复习

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /api/review/due | 获取今日待复习卡片列表 |
| GET | /api/review/new | 获取待学习的新卡片列表 |
| POST | /api/review/{cardId}/rate | 对卡片进行评分（FORGET/VAGUE/FAMILIAR） |

### 4.6 统计

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /api/stats/overview | 获取学习统计概览 |
| GET | /api/stats/deck/{deckId} | 获取牌组级统计 |
| GET | /api/stats/trend | 获取复习趋势数据 |

### 4.7 数据管理

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | /api/backup/export | 导出用户数据快照 |
| POST | /api/backup/import | 导入数据快照（覆盖恢复） |

## 5. 非功能需求

### 5.1 性能

| 编号 | 需求描述 |
|------|---------|
| SQ-01 | 翻页操作响应时间 < 200ms |
| SQ-02 | API 响应时间（95 分位）< 500ms |
| SQ-03 | 支持 1000+ 张卡片的牌组流畅操作 |

### 5.2 安全

| 编号 | 需求描述 |
|------|---------|
| SQ-04 | 密码使用 bcrypt 或类似算法哈希存储 |
| SQ-05 | API 请求使用 JWT Token 鉴权 |
| SQ-06 | 所有 API 通信使用 HTTPS |

### 5.3 数据

| 编号 | 需求描述 |
|------|---------|
| SQ-07 | 数据库定期自动备份 |
| SQ-08 | 用户数据导出格式为 JSON，可读可解析 |

> 卡片快捷导入 JSON 格式：`[{"front":"...","back":"..."}]`，单次最多 1000 张。

### 5.4 兼容性

| 编号 | 需求描述 |
|------|---------|
| SQ-09 | 桌面端支持 Windows、macOS、Linux |
| SQ-10 | 移动端支持 Android、iOS |

### 5.5 时间

| 编号 | 需求描述 |
|------|---------|
| SQ-11 | 所有间隔计算按自然日处理，不精确到小时 |
| SQ-12 | 用户可配置每日刷新时间，默认 04:00，刷新时间过后才计入新的一天 |

## 6. 术语表

| 术语 | 说明 |
|------|------|
| Stage | 卡片所处的学习/复习阶段，决定下次复习间隔 |
| 2^n 队列插入 | 重学期间卡片以 2 的幂次方间距插入复习队列的机制 |
| 连续 Familiar | 在重学阶段需要连续获得 Familiar 评分才能脱离重学 |
| 覆盖恢复 | 导入备份时先删除用户现有数据，再写入备份数据 |
| 富文本 | 支持格式化的文本（粗体、斜体、列表、标题等） |
| LaTeX | 数学公式排版语言 |
| 代码块 | 带语法高亮的代码片段 |
| 自然日 | 日历日，不考虑具体时刻，跨天以用户设定的刷新时间为准 |
| 刷新时间 | 用户自定义的每日重置时间点，用于判断"今天"的范围 |
